T480

A field guide · 2018 → floating around in the market

The ThinkPad you can't kill.

Built in 2018, the ThinkPad T480 remains one of the most heavily modified laptops in circulation. Instead of retiring them, enthusiasts are unlocking their BIOS, dropping in 64 GB of DDR4, upgrading the panels, and running them as primary machines. It represents the end of an era before ultrabooks locked everything down: two physical RAM slots, an external hot-swappable battery, and a mechanical feel that modern chiclet boards still haven't matched.

02 · The overlooked parts

Quiet flexes. Loud payoff.

01

Per-battery charge limits

TLP can set separate thresholds for the internal and external battery, so each pack gets its own ceiling.

02

Two real SO-DIMM slots

Nothing soldered. A thread on the ThinkPads forum covers running 2 × 32 GB, even though Lenovo lists 32 GB.

03

A second NVMe, in the WWAN slot

A 2242 drive can sit where the cellular card goes. Users report it working, with the caveat that some boards run that slot at x2.

04

Two USB-C ports, not twins

Only one does Thunderbolt 3, Power Delivery, DisplayPort and USB 3.1 Gen 2. Plug into the wrong one and a dock quietly underperforms.

05

NFC, SmartCard and ThinkShutter

Optional extras that show up on the right SKU: a webcam shutter, a smart-card reader, NFC under the palm rest.

06

First-class Linux and Qubes support

The Arch wiki keeps a dedicated T480 page, the throttling fix has its own repo, and the Qubes forum runs a long-lived T480 thread.

Coreboot

Supported by coreboot and Libreboot.

The first flash needs a hardware clip on a 16 MiB SOIC-8 chip with a CH341A or Raspberry Pi. Update the stock Thunderbolt firmware first, then use Boot Guard "deguard" and me_cleaner. A bad flash can brick the board.

Works

  • Intel graphics, internal display, mini-DP out
  • Keyboard, TrackPoint, ACPI
  • SATA and NVMe, USB, Ethernet
  • WLAN, WWAN, Bluetooth, VT-x and VT-d
  • NVMe in the WWAN slot

Doesn't

  • Thunderbolt 3 controller
  • Lower-right USB-C beyond charging and DP
  • A reliable MX150
  • Some Fn keys and headphone detect

The only real test is a stress run on your own chip.

If it does nothing, the BIOS may have locked it

Plundervolt mitigations arrived in ThinkPad BIOS updates around late 2019 (an X280 thread cites 1.30). T480 owners on BIOS 1.50 and 1.52 asked modders for a BIOS that unhides the Advanced menu. Downgrading and per-machine modded BIOS files are what people tried, and both carry risk.

Undervolting, step by step.

New to this? Read the four ground rules, pick Windows or Linux, then read the BD PROCHOT card. It is the throttle that most often gets blamed on the wrong thing.

1 · Check it isn't locked

Intel's fix for Plundervolt was a BIOS update that locks voltage to its default settings, so a newer BIOS can make every tool below do nothing.

Windows: press Win+R, type msinfo32 and read BIOS Version/Date. Then apply a small offset in ThrottleStop; if the voltage doesn't change, it's locked.

Linux: run cat /sys/class/dmi/id/bios_version, then sudo intel-undervolt apply and sudo intel-undervolt read; if the values don't move, it's locked.

2 · Start small

Guides start between −50 and −80 mV on core and cache, then step down 5 to 10 mV at a time. Big jumps hide which change broke things. Treat every number in the table above as someone else's chip.

3 · Core and cache together, nothing else

Give core and cache the same offset. Leave analog I/O, digital I/O and system agent at 0. One T480 tuner warns that an unstable uncore offset can corrupt memory silently, with no error in the logs.

4 · Test like you use it

An undervolt can pass a benchmark and still crash at idle, and the least stable place is on battery. After you find the first crash, back off 15 to 20 mV from the deepest clean step, then live with it for days.

Free, no installer. Follow these in order.

  1. Get ThrottleStop from TechPowerUp. Unzip it to a folder you'll keep, then run ThrottleStop.exe as administrator.
  2. Click FIVR. Pick CPU Core, tick Unlock Adjustable Voltage, and choose Adaptive.
  3. Set −50 mV on the Offset slider. Pick CPU Cache and set the same −50. Leave everything else at 0, then press Apply.
  4. Test for 15 minutes. Run Cinebench R23 or Prime95 and watch the temperature. No crash or freeze means it's stable.
  5. Go lower in steps of 10 mV and test again each time. If it crashes, go back up 10 to 20 mV. Many people end up around −100.
  6. Save and autostart. Press OK – Save voltages immediately. Then set ThrottleStop to run at login with Task Scheduler (highest privileges), or the offset is gone after a restart.

Offset does nothing? Check the BIOS lock card above. On Windows 11, Memory integrity can also block it. Turning that off lowers a Windows protection, so it's your call.

Prefer Intel XTU? Set Core Voltage Offset in small steps and use its built-in stress test.

On Linux the offsets are written by a small root daemon at boot. Pick your distro family below for the full install-to-boot steps. If intel-undervolt read shows nothing or the offsets never change, suspect the BIOS lock from the first card.

The other tool: throttled

throttled began as a workaround for throttling on the T480. It also does undervolting. Install it (Arch: sudo pacman -S throttled; Debian and Fedora packages are on its releases page, and it's in Gentoo and Alpine too) and put offsets in the [UNDERVOLT.AC] and [UNDERVOLT.BATTERY] sections of /etc/throttled.conf. Only zero or negative mV values are accepted. Watch it live with sudo throttled --monitor and read logs with journalctl -u throttled.service -b. If you run TLP too, its CPU energy policy settings should be empty when throttled's HWP mode is on.

Both tools write model-specific registers that were found by reverse engineering, and intel-undervolt's own README warns that this may damage hardware. Neither can get past a locked voltage interface.

Must readBD PROCHOT: the throttle that isn't your undervolt

BD PROCHOT is the CPU's emergency "slow down" line. Normal PROCHOT fires when the CPU hits its maximum temperature. The bi-directional version lets other parts of the laptop pull the same line, so the CPU can be throttled hard even when it is not hot. The classic symptom is the clock stuck near 0.8 GHz. One T480 owner thread is titled "throttles to 200 MHz on all cores when plugged into power".

Why it fires

  • A power adapter the laptop doesn't recognise. Some laptops treat third-party or loose chargers as a reason to throttle. A badly seated plug can do it too.
  • Real heat. On one 8th-gen i5-8250U ThinkPad the cause was cooling that could not sustain 40 W. The CPU hit its limit and dropped to about 400 MHz.
  • Another component getting hot. That is what the bi-directional part means.
  • Firmware resetting limits. throttled exists because the firmware on the T480 family keeps resetting the CPU's power limits and temperature target.

How to tell

In ThrottleStop, the Limit Reasons panel lights up for PROCHOT and the BD PROCHOT box. Clock modulation under 100% is another sign. A good undervolt should make the light come on less often.

Fix it in this order

  1. Rule out the charger. Reseat it, then try a genuine adapter of the right wattage. Don't go over what the laptop supports.
  2. Rule out heat. Clean the fan and heatsink and repaste. It was the first advice in that thread.
  3. Use PROCHOT Offset, not the checkbox. In ThrottleStop's Options set PROCHOT Offset to 5 or 10 so the CPU backs off around 90 to 95 °C instead of 100 °C. If it shows a padlock, the BIOS has locked it.
  4. Only then untick BD PROCHOT. It stops other components from throttling the CPU. It is also protection: that same owner found the laptop shut down when BD PROCHOT was disabled, because the CPU kept running at 100 °C. One guide says outright that it does not recommend disabling it. On Windows the setting lasts until restart, so it needs the Task Scheduler autostart from the Windows steps.
  5. Linux: throttled has experimental BD PROCHOT controls, and it restores the power limits the firmware keeps resetting.

If something goes wrong

  • Nothing changes. The BIOS lock, VBS on Windows, or the wrong ThrottleStop profile is highlighted. Run it as administrator.
  • Crash right after applying. Too aggressive. Lower it by 10 to 20 mV and retest.
  • Stable under load, crashes at idle or on battery. Lower it again. This is the most common way an undervolt looks fine and isn't.
  • Resets after reboot. Windows needs the Task Scheduler entry. Linux needs the systemd service enabled.
  • Want to undo it. Set both offsets back to 0 and apply. Stock (0 mV) is where the guides tell you to return after any freeze or crash.

06 · The honest part

Known problems, and the fixes.

Every one of these has a documented fix.

PerformanceIt throttles long before it's hot

What you see

Clocks sag under load and the CPU sits at a low wattage, sometimes while the chassis is barely warm. One thread's user was throttling below 60 °C.

Why

Forum experts blamed firmware: a high PROCHOT offset that trips the thermal brake early, plus power limits lowered on the fly. Ubuntu's bug tracker confirms PL1/PL2 come up wrong, and it persisted on BIOS 1.19.

The fix

Windows: in ThrottleStop turn on PROCHOT Offset, set it to 3 (some pick 10) and tick Lock, then lock the turbo power limits with the MMIO lock option. Apply the same undervolt to core and cache, since core alone did nothing for the thread's author. Start it from Task Scheduler. Linux: run throttled, which rewrites the power registers. It doesn't work with Secure Boot on.

Sources: TechPowerUp thread · Ubuntu bug 1815214

PortsThunderbolt and USB-C stop working

What you see

USB-C or Thunderbolt dead, docks not detected, no HDMI over USB-C, charging capped around 15 W or gone, a Thunderbolt error at POST.

Why

Lenovo said old Thunderbolt 3 firmware wears out the SPI-ROM chip that stores the controller's firmware. T480 owners describe the same symptoms on the forums.

The fix

Install Lenovo's Thunderbolt firmware patch (August 2019, delivered through Lenovo Vantage) before anything else, and don't force-update a controller that's already misbehaving. If the chip is worn, people reflash it with a clip or replace the Winbond SPI chip. Buying used: plug a dock in before you pay.

Sources: Notebookcheck, Thunderbolt 3 failure · ThinkPads forum

PortsThe dock or monitor gets no signal

What you see

A USB-C dock or display works in one port and does nothing in the other.

Why

Only one of the two USB-C ports supports USB 3.1 Gen 2, Power Delivery, DisplayPort and Thunderbolt 3.

The fix

Move the cable to the other USB-C port, and use that port when updating the Thunderbolt firmware.

Sources: CloudsPress T480 upgrade guide

LinuxUndervolt tools do nothing

What you see

intel-undervolt or throttled runs but offsets don't apply, or it errors on MSR access.

Why

With Secure Boot on, the kernel enables Lockdown, which blocks the register access these tools need. Thermald can also fight with them.

The fix

Turn Secure Boot off (or disable the Lockdown LSM) and check that thermald isn't overriding your limits.

Sources: dipch's throttling-fix README

ScreenSome panels flicker

What you see

Eye strain or headaches on some configurations. Notebookcheck flagged specific T480 panels for anyone sensitive to flicker.

Why

PWM backlight dimming on certain panels. The FrankenPad builder also described a high-pitched noise from the stock FHD panel.

The fix

Read the panel part number in the listing before you buy, or swap it. The display connector has four lanes, which is why QHD and 4K panels work. The FrankenPad builder fitted a UHD panel where the PWM frequency could be raised without the whine.

Sources: Notebookcheck review · kitsunyan's FrankenPad write-up

InputTrackPoint dies after suspend

What you see

After waking from sleep, the TrackPoint and touchpad don't respond until a cold boot.

Why

Reported on a T480 board in a modified T25 chassis, so it may be specific to that build.

The fix

That builder found that leaving NFC enabled in the BIOS avoided it. A cold boot is the fallback.

Sources: kitsunyan's FrankenPad write-up

HeatThe chassis runs hot

What you see

Fans spin up, the palmrest warms and the i7 won't hold its boost clocks.

Why

A small heatsink and a slim chassis, plus the firmware limits above.

The fix

Fresh paste first, then the dual heatpipe heatsink, a PTM7950 pad, and liquid metal if you accept the risk. The FrankenPad builder measured an i7-8650U holding about 3.4–3.5 GHz in a 15-minute stress test after liquid metal and an undervolt. Some owners also report copper pads.

Sources: TechPowerUp thread · FrankenPad write-up · Habr

LinuxEverything else: a quick fix list

What you see

Small annoyances that come up again and again on Linux and Windows.

Why

Mostly drivers and power management that need one setting.

The fix

  • Touchpad feel: psmouse synaptics_intertouch=1.
  • Thunderbolt: authorise devices and update through fwupd.
  • Battery swap: shutdown scripts (battery_swap_fix_t480).
  • Fingerprint: kernel 5.8.1+, libfprint-tod or python-validity.
  • Fibocom L850-GL WWAN: no Linux driver.
  • Broadcom Wi-Fi: bcmwl-kernel-source.
  • MX150: proprietary NVIDIA driver.
  • Power: TLP and thinkfan.
  • Windows undervolt reset: run ThrottleStop at logon.
  • Battery drains while shut down: seen with undervolting (Tom's Guide thread).

Sources: Arch wiki · TLP · Tom's Guide · LinuxVox

07 · Verdict

Run it on Linux.

The T480 is old enough that every quirk has been found and written down, and Linux is where that knowledge lives. Install it on Arch, Ubuntu or whatever you like, and you get the most support the machine can have.

Known issues, firmware and power settings in one place.

Undervolt and throttle fixes that work

intel-undervolt and throttled, both with active repositories.

Coreboot, Libreboot and Qubes

Open firmware and a hardened OS are both documented for this board.

Parts you can still buy

Kits, panels, batteries and keyboards are available years after launch.
